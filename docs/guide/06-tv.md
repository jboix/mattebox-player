# 06 TV

This chapter explains how to run the player on a TV, where a remote control
is the only input. `<mbx-spatial-nav>`, from `@mattebox/player-spatial-nav`, moves
focus between the controls with the arrows. The seek bar's
`key-mode="preview"` lets the viewer aim a seek before it happens.
`<mbx-gamepad>`, from the same package, drives the player from a game
controller.

## Install

```sh
npm install @mattebox/player-spatial-nav @mattebox/player mattebox
```

`@mattebox/player` is a peer dependency of the package. The package uses
the player's public types only, like a control of the page's own in
chapter 03. The import registers `<mbx-spatial-nav>` and nothing else. A
page that never runs on a TV leaves the package out and pays nothing.

## Which TVs

The player runs on Chromium 76 and later: Samsung sets on Tizen 6.0 and LG
sets on webOS 6, both from 2021. Older sets are not supported.

- Use the packages' default build or the CDN bundles. Both are ES2015.
- Do not use the `modern` export condition on a TV. It is ES2022, for current browsers.
- Use mattebox 0.8.2 or later. Earlier releases call one API that needs Chromium 85.

## The composition

Place `<mbx-spatial-nav>` anywhere inside the player. It renders nothing.

```html
<mattebox-player src="https://example.com/vod/master.m3u8" controls="custom">
  <mbx-spatial-nav></mbx-spatial-nav>
  <mbx-control-bar seek-step="10">
    <mbx-seek-bar key-mode="preview"></mbx-seek-bar>
    <mbx-scan-button direction="backward"></mbx-scan-button>
    <mbx-play-button></mbx-play-button>
    <mbx-scan-button></mbx-scan-button>
    <mbx-spacer></mbx-spacer>
    <mbx-subtitles-menu></mbx-subtitles-menu>
    <mbx-audio-menu></mbx-audio-menu>
  </mbx-control-bar>
</mattebox-player>
```

## Moving focus

| Key                     | What it does                                                                                                                 |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| An arrow                | Moves focus to the nearest control on that side. The opposite arrow returns to where focus came from                         |
| Left, Right on a slider | Stay the slider's: the seek bar aims or seeks, the volume changes. Up and Down move focus                                    |
| Any key in an open menu | Stays the menu's                                                                                                             |
| The first key           | While the bar is idle, or after a pointer move, only places focus, so a stray arrow never seeks                              |
| An arrow at an edge     | Fires `navigateout` with the direction as `detail`. Your application moves focus out of the player                           |
| Enter                   | Activates the focused control                                                                                                |
| Back                    | Goes back a step: the open menu or the seek bar's target first, then focus leaves the controls, then your application has it |

The first key focuses the control the pointer was over last, then the
control focused last, then the one `initial` names. `initial` takes a tag
name, `mbx-play-button` by default.

A control lies on a side when it lies wholly beyond the edge on that side.
The seek bar spans the row above the buttons, so it is up from every
button, and never left or right of one.

## Seeking with the remote

`key-mode="preview"` on the seek bar makes every seeking key aim instead:

- The arrows on the seek bar, and fast forward and rewind anywhere, move a target. The thumb and the preview show it. The video keeps playing.
- A held key's step grows, so a long film takes seconds to cross.
- Enter seeks. So does moving focus away, or a second without a key.
- Back drops the target.

A TV decodes slowly. One seek per key press stutters, and the preview
already shows where the seek will land. The seek bar's `preview` attribute
picks the picture. `preview="tiles"` spares the TV from decoding frames.

## The remote's keys

Tizen and webOS report some remote keys by their code alone. The element
sends each one on under the name the player reads.

| Key          | Code on Tizen | Code on webOS | Name                                               |
| ------------ | ------------- | ------------- | -------------------------------------------------- |
| Back         | 10009         | 461           | `GoBack`                                           |
| Play/Pause   | 10252         |               | `MediaPlayPause`                                   |
| Play         | 415           | 415           | `MediaPlay`                                        |
| Pause        | 19            | 19            | `MediaPause`                                       |
| Stop         | 413           | 413           | `MediaStop`                                        |
| Fast forward | 417           | 417           | `MediaFastForward`                                 |
| Rewind       | 412           | 412           | `MediaRewind`                                      |
| Arrows       | 37 to 40      | 37 to 40      | `ArrowLeft` to `ArrowDown`, when the name is empty |
| OK           | 13            | 13            | `Enter`, when the name is empty                    |

The control bar handles the media keys: play, pause, and Stop pauses. Fast
forward and rewind seek by the bar's `seek-step`, and aim under
`key-mode="preview"`. They never scan; the scan buttons do.

Your application registers the media keys with the platform. The player
never does. On Tizen:

```js
tizen.tvinputdevice.registerKeyBatch([
  'MediaPlayPause',
  'MediaPlay',
  'MediaPause',
  'MediaStop',
  'MediaFastForward',
  'MediaRewind',
]);
```

Back is also your application's once it leaves the player. On Tizen,
`tizen.application.getCurrentApplication().exit()` closes the application.

## Leaving the player

`navigateout` bubbles and is composed. Listen on the player, and move focus
to your own navigation:

```js
player.addEventListener('navigateout', (event) => {
  if (event.detail === 'down') document.querySelector('#rail button').focus();
});
```

To come back, focus a control inside the player, such as the play button:

```js
player.querySelector('mbx-play-button').shadowRoot.querySelector('button').focus();
```

## Game controllers

`<mbx-gamepad>` drives the player from a game controller. Place it beside
`<mbx-spatial-nav>`, which it relies on to move focus. It renders nothing.

The controller is a second entry of the package, so a page with a remote
alone pays nothing for it. The entry registers `<mbx-spatial-nav>`,
`<mbx-gamepad>` and `<mbx-gamepad-help>`.

```js
import '@mattebox/player-spatial-nav/gamepad';
```

From a CDN, load `dist/cdn/mattebox-player-spatial-nav-gamepad.min.js` in
place of the spatial navigation's bundle. It holds both.

```html
<mattebox-player src="https://example.com/vod/master.m3u8" controls="custom">
  <mbx-spatial-nav></mbx-spatial-nav>
  <mbx-gamepad></mbx-gamepad>
  <mbx-gamepad-help></mbx-gamepad-help>
  <mbx-control-bar>…</mbx-control-bar>
</mattebox-player>
```

The element reads the pads once a frame, only while one is connected and
the page is visible. A browser reports a pad after its first press.

### The default buttons

Buttons are named by their place, so one mapping fits every make. `south`
is the lower face button: A on an Xbox pad, Cross on a PlayStation pad, B
on a Nintendo pad.

| Button     | Xbox   | PlayStation | Nintendo | Action                          |
| ---------- | ------ | ----------- | -------- | ------------------------------- |
| d-pad      | d-pad  | d-pad       | d-pad    | `up`, `down`, `left`, `right`   |
| left stick | LS     | L3          | LS       | The same as the d-pad           |
| `south`    | A      | Cross       | B        | `activate` (`back` on Nintendo) |
| `east`     | B      | Circle      | A        | `back` (`activate` on Nintendo) |
| `west`     | X      | Square      | Y        | None                            |
| `north`    | Y      | Triangle    | X        | `subtitles`                     |
| `lb`, `rb` | LB, RB | L1, R1      | L, R     | `previous`, `next`              |
| `lt`, `rt` | LT, RT | L2, R2      | ZL, ZR   | `rewind`, `fast-forward`        |
| `select`   | View   | Create      | −        | `help`                          |
| `start`    | Menu   | Options     | +        | `play-pause`                    |

A Nintendo pad selects with A and goes back with B, as Nintendo's own
software does. A sits on the right, so `east` activates there. The Xbox,
PlayStation and Home buttons belong to the system and are never read.

The make comes from the pad's USB vendor id, then its name. Any other pad
is taken for an Xbox pad, the layout most pads follow.

| Action                   | What it does                                                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `up` … `right`           | The arrow keys: focus moves. They repeat while held                                                                                         |
| `activate`               | Enter on the focused control. With no control focused, or the bar asleep, play or pause                                                     |
| `back`                   | The remote's Back. With no control focused in fullscreen, fullscreen ends first                                                             |
| `play-pause`             | Plays or pauses                                                                                                                             |
| `rewind`, `fast-forward` | Seek by the bar's `seek-step`, again while held, faster the harder the trigger is pressed                                                   |
| `previous`, `next`       | The chapter before or after, else the playlist's previous or next item. Past the first 3 seconds of a chapter, `previous` goes to its start |
| `subtitles`              | Opens the subtitles menu                                                                                                                    |
| `mute`                   | Mutes or unmutes                                                                                                                            |
| `fullscreen`             | Enters or leaves fullscreen                                                                                                                 |
| `help`                   | Opens or closes `<mbx-gamepad-help>`                                                                                                        |

The actions send the keys a remote sends, so `key-mode="preview"` on the
seek bar aims with the triggers too.

The browser shows a focus ring only after a real key, and the pad's keys
are synthetic. A press of the pad sets `focus-ring` on the player, so the
focused control shows its ring and its name. A pointer's press takes it
off.

### Changing the buttons

`map` lists the buttons to change, as `button:action` pairs. `none`
unbinds a button.

```html
<mbx-gamepad map="west:mute north:fullscreen select:none"></mbx-gamepad>
```

The `map` property does the same from script, over the attribute. `null`
unbinds a button.

```js
const gamepad = player.querySelector('mbx-gamepad');
gamepad.map = { west: 'mute', lt: 'previous', rt: 'next', lb: null, rb: null };
```

`gamepad.bindings()` returns what each button does on the pad in use, after
the defaults, the attribute and the property. `gamepad.kind` is the make of
that pad: `xbox`, `playstation` or `nintendo`.

### Your own actions

Every press fires `gamepadaction` on the element first. It bubbles, is
composed, and is cancellable. `detail` holds the `action`, the `button`
and the pad's `kind`. Cancel it to do something else.

An action of your own name only fires the event:

```js
gamepad.map = { west: 'add-to-list' };
player.addEventListener('gamepadaction', (event) => {
  if (event.detail.action === 'add-to-list') addToList();
});
```

`gamepadconnect` and `gamepaddisconnect` fire on the element when a pad
comes and goes, with the `kind` and the `id` in `detail`.

### The controls bubble

`<mbx-gamepad-help>` lists what each button does, over the video. It reads
the mapping from `<mbx-gamepad>`, your changes included, and prints the
buttons as the make of the pad in use does.

- It opens when a pad connects, and closes after `close-ms`, 6000 by default.
- `manual` keeps it closed until the `help` action, View by default.
- Back closes it, and goes no further.
- `label` names the bubble, "Controller" by default.
- `label-<action>` names an action, such as `label-next="Next episode"`.
  An action of your own shows only with a label.

| Part      | What it is                      |
| --------- | ------------------------------- |
| `bubble`  | The box                         |
| `heading` | The name                        |
| `list`    | The list of buttons and actions |
| `button`  | One button                      |

The element carries `kind` with the make it shows, for a style per make.

### Where pads work

The Gamepad API is in every current browser and in Chromium 76.

- Desktop browsers, and the Steam Deck.
- Edge on Xbox. It moves a mouse cursor with the pad unless the page asks
  for the pad, which the element does through
  `navigator.gamepadInputEmulation`.
- Android TV, and TVs with a paired pad, where the TV's browser exposes it.
- The consoles' own video apps are native and do not run a web page.

### Testing without a pad

`navigator.getGamepads` is a function you replace in a test. Return a pad
with the `standard` mapping, then fire `gamepadconnected` on the window.
Change a button's `pressed` and `value`, and wait two animation frames.

```js
const pad = {
  id: 'Xbox Wireless Controller (STANDARD GAMEPAD Vendor: 045e)',
  index: 0,
  connected: true,
  mapping: 'standard',
  axes: [0, 0, 0, 0],
  buttons: Array.from({ length: 17 }, () => ({ pressed: false, value: 0 })),
};
navigator.getGamepads = () => [pad];
window.dispatchEvent(Object.assign(new Event('gamepadconnected'), { gamepad: pad }));
pad.buttons[9] = { pressed: true, value: 1 }; // Menu: play or pause
```

## Example

The demo's TV setup composes the player this way, and its markup panel
gives you the code to copy. Choose TV under Setup, then use the arrow keys
on the player.

The example adds a row of your own under the player, which `navigateout`
reaches.

```html
<mattebox-player id="player" src="https://example.com/vod/master.m3u8" controls="custom" muted>
  <mbx-spatial-nav></mbx-spatial-nav>
  <mbx-gamepad></mbx-gamepad>
  <mbx-gamepad-help></mbx-gamepad-help>
  <mbx-title heading="A film"></mbx-title>
  <mbx-start-button></mbx-start-button>
  <mbx-spinner></mbx-spinner>
  <mbx-control-bar seek-step="10">
    <mbx-current-time></mbx-current-time>
    <mbx-seek-bar key-mode="preview" preview="tiles"></mbx-seek-bar>
    <mbx-duration></mbx-duration>
    <mbx-scan-button direction="backward"></mbx-scan-button>
    <mbx-play-button></mbx-play-button>
    <mbx-scan-button></mbx-scan-button>
    <mbx-spacer></mbx-spacer>
    <mbx-chapters-menu></mbx-chapters-menu>
    <mbx-subtitles-menu></mbx-subtitles-menu>
  </mbx-control-bar>
</mattebox-player>
<nav id="rail"><button type="button">Another film</button></nav>

<script type="module">
  import '@mattebox/player';
  import '@mattebox/player-spatial-nav/gamepad';

  const player = document.getElementById('player');
  player.addEventListener('navigateout', (event) => {

</script>
```
