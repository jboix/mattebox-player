# 06 TV

This chapter explains how to run the player on a TV, where a remote control
is the only input. `<mbx-spatial-nav>`, from `@mattebox/player-spatial-nav`, moves
focus between the controls with the arrows. The seek bar's
`key-mode="preview"` lets the viewer aim a seek before it happens.

## Install

```sh
npm install @mattebox/player-spatial-nav @mattebox/player mattebox
```

`@mattebox/player` is a peer dependency of the package. The package uses
the player's public types only, like a control of the page's own in
chapter 03. The import registers `<mbx-spatial-nav>` and nothing else. A
page that never runs on a TV leaves the package out and pays nothing.

## Which TVs

The player runs on Chromium 76 and later: Samsung sets on Tizen 6.0 and LG
sets on webOS 6, both from 2021. Older sets are not supported.

- Use the packages' default build or the CDN bundles. Both are ES2015.
- Do not use the `modern` export condition on a TV. It is ES2022, for current browsers.
- Use mattebox 0.8.2 or later. Earlier releases call one API that needs Chromium 85.

## The composition

Place `<mbx-spatial-nav>` anywhere inside the player. It renders nothing.

```html
<mattebox-player src="https://example.com/vod/master.m3u8" controls="custom">
  <mbx-spatial-nav></mbx-spatial-nav>
  <mbx-control-bar seek-step="10">
    <mbx-seek-bar key-mode="preview"></mbx-seek-bar>
    <mbx-scan-button direction="backward"></mbx-scan-button>
    <mbx-play-button></mbx-play-button>
    <mbx-scan-button></mbx-scan-button>
    <mbx-spacer></mbx-spacer>
    <mbx-subtitles-menu></mbx-subtitles-menu>
    <mbx-audio-menu></mbx-audio-menu>
  </mbx-control-bar>
</mattebox-player>
```

## Moving focus

| Key                     | What it does                                                                                                                 |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| An arrow                | Moves focus to the nearest control on that side. The opposite arrow returns to where focus came from                         |
| Left, Right on a slider | Stay the slider's: the seek bar aims or seeks, the volume changes. Up and Down move focus                                    |
| Any key in an open menu | Stays the menu's                                                                                                             |
| The first key           | While the bar is idle, or after a pointer move, only places focus, so a stray arrow never seeks                              |
| An arrow at an edge     | Fires `navigateout` with the direction as `detail`. Your application moves focus out of the player                           |
| Enter                   | Activates the focused control                                                                                                |
| Back                    | Goes back a step: the open menu or the seek bar's target first, then focus leaves the controls, then your application has it |

The first key focuses the control the pointer was over last, then the
control focused last, then the one `initial` names. `initial` takes a tag
name, `mbx-play-button` by default.

A control lies on a side when it lies wholly beyond the edge on that side.
The seek bar spans the row above the buttons, so it is up from every
button, and never left or right of one.

## Seeking with the remote

`key-mode="preview"` on the seek bar makes every seeking key aim instead:

- The arrows on the seek bar, and fast forward and rewind anywhere, move a target. The thumb and the preview show it. The video keeps playing.
- A held key's step grows, so a long film takes seconds to cross.
- Enter seeks. So does moving focus away, or a second without a key.
- Back drops the target.

A TV decodes slowly. One seek per key press stutters, and the preview
already shows where the seek will land. The seek bar's `preview` attribute
picks the picture. `preview="tiles"` spares the TV from decoding frames.

## The remote's keys

Tizen and webOS report some remote keys by their code alone. The element
sends each one on under the name the player reads.

| Key          | Code on Tizen | Code on webOS | Name                                               |
| ------------ | ------------- | ------------- | -------------------------------------------------- |
| Back         | 10009         | 461           | `GoBack`                                           |
| Play/Pause   | 10252         |               | `MediaPlayPause`                                   |
| Play         | 415           | 415           | `MediaPlay`                                        |
| Pause        | 19            | 19            | `MediaPause`                                       |
| Stop         | 413           | 413           | `MediaStop`                                        |
| Fast forward | 417           | 417           | `MediaFastForward`                                 |
| Rewind       | 412           | 412           | `MediaRewind`                                      |
| Arrows       | 37 to 40      | 37 to 40      | `ArrowLeft` to `ArrowDown`, when the name is empty |
| OK           | 13            | 13            | `Enter`, when the name is empty                    |

The control bar handles the media keys: play, pause, and Stop pauses. Fast
forward and rewind seek by the bar's `seek-step`, and aim under
`key-mode="preview"`. They never scan; the scan buttons do.

Your application registers the media keys with the platform. The player
never does. On Tizen:

```js
tizen.tvinputdevice.registerKeyBatch([
  'MediaPlayPause',
  'MediaPlay',
  'MediaPause',
  'MediaStop',
  'MediaFastForward',
  'MediaRewind',
]);
```

Back is also your application's once it leaves the player. On Tizen,
`tizen.application.getCurrentApplication().exit()` closes the application.

## Leaving the player

`navigateout` bubbles and is composed. Listen on the player, and move focus
to your own navigation:

```js
player.addEventListener('navigateout', (event) => {
  if (event.detail === 'down') document.querySelector('#rail button').focus();
});
```

To come back, focus a control inside the player, such as the play button:

```js
player.querySelector('mbx-play-button').shadowRoot.querySelector('button').focus();
```

## Example

The demo's TV setup composes the player this way, and its markup panel
gives you the code to copy. Choose TV under Setup, then use the arrow keys
on the player.

The example adds a row of your own under the player, which `navigateout`
reaches.

```html
<mattebox-player id="player" src="https://example.com/vod/master.m3u8" controls="custom" muted>
  <mbx-spatial-nav></mbx-spatial-nav>
  <mbx-title heading="A film"></mbx-title>
  <mbx-start-button></mbx-start-button>
  <mbx-spinner></mbx-spinner>
  <mbx-control-bar seek-step="10">
    <mbx-current-time></mbx-current-time>
    <mbx-seek-bar key-mode="preview" preview="tiles"></mbx-seek-bar>
    <mbx-duration></mbx-duration>
    <mbx-scan-button direction="backward"></mbx-scan-button>
    <mbx-play-button></mbx-play-button>
    <mbx-scan-button></mbx-scan-button>
    <mbx-spacer></mbx-spacer>
    <mbx-chapters-menu></mbx-chapters-menu>
    <mbx-subtitles-menu></mbx-subtitles-menu>
  </mbx-control-bar>
</mattebox-player>
<nav id="rail"><button type="button">Another film</button></nav>

<script type="module">
  import '@mattebox/player';
  import '@mattebox/player-spatial-nav';

  const player = document.getElementById('player');
  player.addEventListener('navigateout', (event) => {
    if (event.detail === 'down') document.querySelector('#rail button').focus();
  });
</script>
```
